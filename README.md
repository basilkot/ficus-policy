# ficusapps.com

Сайт `ficusapps.com`. Три задачи, и все три — про то, чтобы приложение можно было найти:

1. **Короткий адрес для картинок.** Коллаж и итог года уходят наружу с подписью
   `ficusapps.com/beauty`. Это должен быть адрес, который набирают руками с картинки, —
   отсюда `/beauty`, а не `/beauty-stuff-ios` и не ссылка в стор длиной в строку.
2. **Переход в нужный стор.** Одна ссылка на две платформы: с iPhone уводит в App Store,
   с Android — в Play, с компьютера показывает QR. Приложение, отправляя картинку,
   не знает, с какого устройства её откроют, и знать не должно.
3. **Метка, откуда пришли.** `?from=collage`, `?from=year`, `?from=qr` доезжают до сторов
   параметрами кампании — иначе нельзя узнать, приносит ли коллаж установки вообще.

Здесь же живут политики и страницы поддержки — те, на которые ссылаются карточки обоих
сторов. Раньше у них был свой репозиторий: он появился раньше домена просто потому, что
публичный адрес был нужен, а взять его было неоткуда. С доменом эта причина исчезла.

Статика. Сервер для этого не нужен: страницы не меняются между запросами, а раздача с CDN
надёжнее и быстрее одной машины. Собранный `dist/` одинаково ложится и на GitHub Pages,
и на nginx, если сервер всё-таки появится.

## Устройство

| Что | Где |
|---|---|
| Адреса приложений в сторах, сборка ссылок с кампанией | [`src/data/apps.ts`](src/data/apps.ts) |
| Страница перехода — то, куда ведёт короткий адрес | [`src/components/AppGate.astro`](src/components/AppGate.astro) |
| QR, посчитанный на сборке | [`src/components/QR.astro`](src/components/QR.astro) |
| Обвязка страницы и теги превью | [`src/layouts/Page.astro`](src/layouts/Page.astro) |
| Политики и поддержка — целыми файлами | [`public/beauty-stuff/`](public/beauty-stuff/), [`public/beauty-stuff-ios/`](public/beauty-stuff-ios/) |
| Их опись для корневой страницы | [`src/data/documents.ts`](src/data/documents.ts) |

Новое приложение добавляется одной записью в `src/data/apps.ts` и парой страниц-обёрток
в `src/pages/<slug>/` — всё остальное собирается из реестра.

**Английская версия в корне, русская в `/ru/`** — так же, как в политиках и в самих
приложениях. Приложение подставляет в отправляемый текст адрес по языку интерфейса,
а в картинке печатается всегда короткий `ficusapps.com/beauty`.

**Документов два на приложение, и это не перевод одного.** Android- и iOS-версии собирают
данные по-разному, а политика описывает состав собираемого — общий документ был бы неверен
для обеих. Английский текст лежит в корне раздела, русский в `ru/`: русская карточка в Play
ссылается прямо на `/beauty-stuff/ru/`, остальные — на `/beauty-stuff/`. У iOS так же,
с версии 1.1: русская локаль в App Store Connect смотрит на `/beauty-stuff-ios/ru/`
и `/beauty-stuff-ios/support/ru/`, остальные одиннадцать — на адреса без `/ru/`.
Приложение выбирает страницу само, по языку интерфейса.

**Политики не собираются, а лежат.** Единственный источник правды у политики — файл внутри
самого приложения: человек читает её прямо там, и расхождение между двумя текстами — ровно
то, к чему придирается Play. Поэтому страница копируется сюда без изменений, и всё, что
умеет менять текст по дороге — шаблоны, общая обвязка, подстановка года, — ей
противопоказано. Правится сначала в репозитории приложения, сюда копируется следом.

Пути у них те же, что были на `basilkot.github.io/ficus-policy/`, до последнего слеша.
Это не совпадение: одинаковые пути превращают переезд в подстановку домена — и в старых
адресах, и в карточках сторов.

## Разработка

```sh
npm install
npm run dev      # http://localhost:4321
npm run build    # dist/
```

Страница перехода с телефона уводит в стор мгновенно — посмотреть её саму можно
по `?stay=1`.

## Публикация

`public/CNAME` уже содержит домен. Чтобы он заработал, у регистратора нужны записи:

```
A     @    185.199.108.153
A     @    185.199.109.153
A     @    185.199.110.153
A     @    185.199.111.153
AAAA  @    2606:50c0:8000::153
AAAA  @    2606:50c0:8001::153
AAAA  @    2606:50c0:8002::153
AAAA  @    2606:50c0:8003::153
CNAME www  basilkot.github.io.
```

Адреса общие для всех сайтов на Pages, и своего среди них нет ни у кого: какой из них
чей — GitHub решает по домену в `public/CNAME`. Записи и файл работают только вместе,
поэтому домен, поменянный в одном месте, нужно менять и во втором.

Четыре адреса в каждой паре — на случай, если одна площадка недоступна. Каждый из них
anycast: за номером стоит много машин по миру, и запрос приходит на ближайшую.

Дальше в настройках репозитория — Pages, ветка публикации, и галочка «Enforce HTTPS»
после того, как сертификат выпустится.

## Чего ещё нет

- **Токен провайдера App Store Connect** (`appleProviderToken` в `src/data/apps.ts`).
  Пока его нет, метка кампании до отчётов Apple не доезжает: Apple считает разбивку
  только по паре `pt` + `ct`. Ссылка при этом рабочая — не работает измерение.
- **Картинка превью.** `og:image` пока указывает на иконку. Для Pinterest нужен
  горизонтальный баннер — это часть разговора про то, как выглядит сам коллаж.
- **Отключение старого репозитория.** Копии политик уже здесь, но `ficus-policy` пока
  работает и остаётся единственным, что держит ссылки из карточек. Порядок переезда
  ниже, и он не переставляется.

## Как обновлять политику

Правим сначала в репозитории приложения, а сюда копируем без изменений:

```sh
cp ../beauty-stuff/app/src/main/assets/policy-en.html public/beauty-stuff/index.html
cp ../beauty-stuff/app/src/main/assets/policy-ru.html public/beauty-stuff/ru/index.html
cp ../beauty-stuff-ios/docs/privacy/index.html public/beauty-stuff-ios/index.html
cp ../beauty-stuff-ios/docs/privacy/ru/index.html public/beauty-stuff-ios/ru/index.html
cp ../beauty-stuff-ios/docs/support/index.html public/beauty-stuff-ios/support/index.html
cp ../beauty-stuff-ios/docs/support/ru/index.html public/beauty-stuff-ios/support/ru/index.html
```

и проверяем, что копии совпали:

```sh
diff public/beauty-stuff/index.html ../beauty-stuff/app/src/main/assets/policy-en.html
diff public/beauty-stuff/ru/index.html ../beauty-stuff/app/src/main/assets/policy-ru.html
diff public/beauty-stuff-ios/index.html ../beauty-stuff-ios/docs/privacy/index.html
diff public/beauty-stuff-ios/ru/index.html ../beauty-stuff-ios/docs/privacy/ru/index.html
diff public/beauty-stuff-ios/support/index.html ../beauty-stuff-ios/docs/support/index.html
diff public/beauty-stuff-ios/support/ru/index.html ../beauty-stuff-ios/docs/support/ru/index.html
```

Дату в начале документа меняем при каждом изменении состава собираемых данных.

## Переезд политик со старого адреса

Репозиторий остался тем же, в котором политики лежали всегда, — и это снимает почти всю
работу по переезду. Как только домен привязан в настройках Pages, GitHub сам уводит
`basilkot.github.io/ficus-policy/...` на `ficusapps.com/...`, путь в путь. Ссылки в карточках
обоих сторов продолжают работать, ничего не делая: они ведут на старый адрес, а тот
перенаправляет на новый.

Пути внутри `public/` поэтому и повторяют прежние до последнего слеша. Ровно из-за этого
переезд оказался подстановкой домена, а не переписыванием ссылок.

Остаётся необязательное:

- **Обновить карточки сторов** на прямые адреса `ficusapps.com/...` — App Store Connect
  по одной ссылке на локаль, Play Console в разделе App content. Не срочно: пока не сделано,
  всё работает через перенаправление GitHub. Смысл в том, чтобы не зависеть от него вечно.
- **Переименовать репозиторий** — `ficus-policy` теперь описывает меньшую его часть.
  После привязки домена имя в адресах не участвует, так что это косметика. Делать её стоит
  после предыдущего пункта: пока карточки смотрят на старый адрес, лишний раз трогать
  то, через что этот адрес работает, незачем.
